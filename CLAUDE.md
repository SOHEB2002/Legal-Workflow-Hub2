## The proven cast-cleanup pipeline
1. **Inventory:** grep counts + categorize (VESTIGIAL / TYPE_MISMATCH / FIELD_NOT_ON_TYPE / MAP_INDEX / LEGITIMATE).
2. **Controlled experiment:** strip casts → `npx tsc --noEmit` → capture surfaced errors → revert.
3. Vestigial (no error) → delete. Value mismatch → precise type (`as ProperUnion`). Map-index → `as Record<string,string>`. Field-not-on-type → **DIAGNOSE** (could be a bug — e.g. the `assigned_to` NOT NULL finding). Legitimate (`catch (e: any)`, multer `req.file`, raw JSON `any[]`) → keep.
4. NEVER re-add blanket `as any`. NEVER relocate a cast to silence an error.
5. **Gates before commit:** tsc = 0; grep verification counts; `git diff | grep "^+" | grep "as any"` shows only precise casts; behavior unchanged.
6. Commit messages document findings (root fixes like `role: UserRoleType`, `PriorityType`) so diffs self-explain.
- **Vestigial-cast philosophy:** ~90% of `as any` is stale residue from the additive-only schema — `LawCase` (and sibling interfaces) already have the fields the casts strip (`isArchived`, `clientRole`, `grievanceRequired`, najiz/mohr/taradi fields, etc.). Removing them INCREASES safety by re-enabling typo detection. Verify each field against the relevant `shared/schema.ts` interface before removing.
- **Transient-API-field pattern:** request-body fields that are NOT entity columns (e.g. `startingStage`, `stageChangeNotes`) use `as Partial<LawCase> & { field?: T }`, NOT `as any`.

#### 🔴 THE MODEL CORRECTION — read this before touching anything judgment-related (`a3f7897`)
The form used to ask **"درجة الحكم: ابتدائي أم نهائي"**. That is a **FALSE OPPOSITION**: the opposite of `ابتدائي` is **`استئنافي`**; `نهائي` is a **separate property** (can the ruling still be objected to). The model now:
- **THE DEGREE IS DERIVED FROM THE CASE PATH, NEVER ASKED** — `منظورة` → the ruling is `ابتدائي`; `منظورة_استئناف` → the ruling is `استئنافي`, final by nature. Shown read-only in the dialog.
- **The ONLY judgment question besides the outcome is OBJECTIONABILITY** — "هل الحكم قابل للاعتراض؟" `نعم`/`لا`, a **required tri-state**, asked only for a first-instance ruling. (Deliberately NOT narrowed to one court type — non-objectionability is a property of the ruling.)
- **FINALITY IS COMPUTED:** `isFinal = isAppealRuling || objectionable === false`. `judgmentFinal` is **never sent by the client**; the server derives it and writes it to `hearings.judgment_final` so every existing reader (isFinal branches, the detail badge, stats, `findPrimaryJudgmentHearing`) keeps working.
- **RESULTING STAGE:** `منظورة`+قابل → `محكوم_حكم_ابتدائي` · `منظورة`+غير قابل → **`محكوم_حكم_نهائي` directly** (skips the صك flow, the objection memo and the appeal path entirely) · `منظورة_استئناف`+any → `محكوم_حكم_نهائي`.
- **CHECKBOXES → REQUIRED TRI-STATE SELECTS (`aa1e5c3`), a permanent lesson:** a checkbox cannot distinguish *"the lawyer answered NO"* from *"the lawyer didn't answer"*, and that ambiguity was producing dead-end cases. Any judgment-shaped question gets a tri-state.
- **NO BLOCKING GUARD AT JUDGMENT TIME (`6503108`, owner decision).** A judgment recorded on a case that is at neither court stage **silently PROMOTES it** (منظورة + قيد_الدراسة → منظورة_بالمحكمة, clientRole ||= مدعي) and then proceeds. The guard belongs at HEARING CREATION, not here. Do not re-add a block.
